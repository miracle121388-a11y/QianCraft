# 人工决策工作流

QianCraft 0.6.0 在系统推荐链路之外增加一层可持久化的人工决策。目标不是让人工修改文化事实或市场原记录，而是让团队明确决定“本轮使用什么、如何权衡、往哪个设计方向继续”。

## 七个决策阶段

| 阶段 | 人工可调整 | 保持只读的证据 |
|---|---|---|
| 文化选材 | 从 22 条贵州文化记录中多选本轮输入 | 名称、地域、工艺、纹样、文化边界与 `Cxxx` 来源 |
| 市场范围 | 选择小红书、抖音、B站、微博及 Top 10 产品形态 | 平台状态、样本量、原始快照与 `Mxxx` 引用 |
| 评分与候选 | 精确输入六维权重、风险扣分并选 1–3 个机会 | 六维原始分、系统总分与核验状态 |
| 设计意图 | 目标人群、价格带、产品形态、场景与材料偏好 | 上游文化和市场事实 |
| 视觉方向 | 研究参照、风格关键词、画幅和禁用说明 | `reference_only` 权利状态与馆藏出处 |
| 方案比较 | 选择 A/B/C 比较组与当前采用方案 | 已生成版本和历史资产 |
| 海报呈现 | 编辑提案、工坊拆解或展陈海报主题，以及板块显隐 | 概念/首样边界与引用台账 |

## 数据契约

工作区使用 `schema_version: 1.1`。人工选择保存在 `metadata.decision_profile`，计算结果保存在 `metadata.decision_output`：

- `mode` 区分 `guided` 系统建议和 `manual` 人工配置；
- `version` 每次成功保存递增，节点显示 `HUMAN vN`；
- `scoreWeights` 保存六个正向维度，服务端在保存时归一化；
- `culturalRiskPenalty` 独立于正向权重，不会被归一化；
- `systemScore` 始终保留，`manualScore` 另行计算，避免人工结果冒充系统原分；
- 文化、市场、视觉参照和概念只保存稳定 ID，不复制或改写事实正文。

## API

```http
POST /api/workbench/workspaces/{workspace_id}/decisions
Content-Type: application/json

{
  "decision_profile": { "...": "完整 DecisionProfile" }
}
```

服务端会校验记录、平台、产品形态、机会、视觉参照与概念 ID；文化/平台/产品形态/机会/比较组/海报板块至少保留一项，机会最多三项。未知 ID、无效画幅、无效主题或全零权重返回 `422`，不会写入工作区。

`GET /api/workbench/bootstrap` 同时返回 `decisionCatalog`，前端不需要硬编码文化记录、机会、视觉参照或概念清单。

## 下游失效语义

保存人工决策后：

1. 文化、市场和机会节点立即显示本轮选择及人工排序；
2. 设计任务书接收人群、品类、场景和材料优先级，并生成新版本；
3. 任务书、视觉生成、概念和海报节点统一标记为 `stale`，提示团队确认或重跑；
4. 只有加入比较组的概念会进入后续视觉生成；
5. 当前采用概念继续驱动海报，但在重跑前不会被宣称为新完成结果。

这套失效规则避免“改了上游，旧海报仍显示已完成”的假一致性。

## 页面入口

- 顶部“人工决策”按钮从当前选中节点进入对应阶段；
- 左侧证据中心可直接进入文化选材或市场范围；
- 画布状态条可直接进入评分阶段；
- Inspector 参数页显示本节点的人工决策版本；
- 九个节点展示页均提供“人工决策”深链接，并携带工作区 ID 和对应阶段。

## 边界

人工决策只改变项目取舍，不授予文化或视觉权利，也不改变历史平台快照的时效状态。当前输出仍止于 `DesignPackage`、工厂询价/首样沟通和概念海报；生产发布、工厂下单、商业图稿审批与合规就绪声明不在授权范围内。
