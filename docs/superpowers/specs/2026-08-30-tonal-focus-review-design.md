# QianCraft Tonal Focus Review 前端重构设计

日期：2026-08-30
状态：用户已批准，待按实施计划执行
已选构图：C2 `.impeccable/mocks/tonal-focus-review.png`

## 1. 背景与目标

QianCraft 已有完整工作台、节点详情、Human Decision Studio、文化关系图和持续采集控制面，但现有视觉方向不再符合用户对“简约、有颜色、不过度装饰”的要求。本轮目标是先做出一版可运行的网站，供评委现场观看并在后续轮次继续微调。

实现必须保留现有 HTTP 接口、工作区持久化、九个真实节点、十条真实连线、节点动作、证据引用、详情深链、Decision Studio、文化关系图、采集状态和移动端能力。视觉重构不得制造实时平台授权、生产就绪或文化事实。

## 2. 非目标

- 不修改 Python 后端、API 契约、证据数据或模型调用流程。
- 不新增前端依赖，不引入主题框架、图表库或装饰性动画库。
- 不把构图中的虚构缩略图、时间、人名、节点标签或连线复制到产品。
- 不进行线上部署、工厂下单、商业图稿审批或量产/合规声明。
- 不把当前被阻断的四平台实时采集描述成已连接或持续在线。

## 3. 视觉系统

采用 C2 “Tonal Focus Review”。大面积纯白被低饱和实色色块替代，颜色只承担区域、选择、焦点或状态语义。

| 角色 | 色值 | 用途 |
|---|---:|---|
| 应用外壳 | `#E6E2DA` | 页面底色、外围留白 |
| 命令栏 | `#D9E1E8` | 全局导航与工作区控制 |
| 工具/证据 | `#D7E1DC` | 左侧工具栏、底部证据抽屉 |
| 主画布 | `#E3E8EB` | React Flow 工作面 |
| Inspector | `#E7DDD4` | 选中节点详情与操作 |
| 节点表面 | `#F0EEE9` | 未选节点与局部内容面 |
| 选中表面 | `#CBD9E6` | 当前节点 |
| 主动作/焦点 | `#345C7D` | 主按钮、选中边线、焦点环 |
| 主文字 | `#20262C` | 标题与正文 |
| 次级文字 | `#626970` | 元信息与说明 |
| 分隔线 | `#C4C8C7` | 边界与结构线 |
| 状态色 | `#637E6A` / `#B1844C` / `#9A6757` / `#7B8086` | 完成、警告、错误/阻断、中性 |

禁止渐变、玻璃、模糊光晕、霓虹、高饱和环境色、民族纹样装饰、营销首屏和无意义悬浮卡片。圆角限制为 10–14px；只有重叠的 Inspector 或移动端抽屉可以使用克制阴影。

## 4. 信息架构与桌面构图

1280px 及以上使用完整工作台：

1. 顶部 60px 命令栏保留品牌、工作区、阶段切换、Human Decision v2 和“运行当前节点”。
2. 左侧 72px 工具栏切换画布、证据、素材、记录和相关工具，不重复顶部阶段导航。
3. 中央 React Flow 画布使用真实九节点、十连线和现有视口状态。选择节点不会改变节点尺寸或拓扑。
4. 画布底部提供约 210px 上下文抽屉。默认显示与所选节点相关的真实证据；同一位置可切换素材或历史记录，不永久堆叠多个面板。
5. 右侧约 330px Inspector 绑定所选节点，承载概览、输入、配置、结果、证据、记录和操作。它从右侧轻微覆盖画布与底部抽屉，不挤压节点几何。

选择节点时，仅改变节点表面、边线和绑定内容；Inspector 与证据抽屉可使用短时透明度/位移动效，但不得产生布局跳动。

## 5. 页面与组件责任

### AppBar

保留当前工作区和阶段语义。主动作始终只有一个，使用 `#345C7D`；保存、运行和危险动作继续通过真实状态禁用或显示结果，不使用演示假成功。

### ToolRail 与 Context Drawer

工具栏只负责切换工作面。证据、素材和历史沿用现有数据与动作，在底部上下文抽屉中显示。可拖拽项目继续保留可见的“添加到画布”按钮，确保拖拽不是唯一入口。

### FocusCanvas

React Flow 的平移、框选、滚轮/捏合缩放和节点拖动行为不变。节点视觉统一为轻石色条目；类别、状态、更新提示和选中态使用文本/图标/形状与低饱和颜色共同表达。

### Inspector

沿用现有节点详情、编辑、保存、运行、重新生成、导出和下载能力。信息采用清晰分组与渐进披露，不在画布节点内重复长摘要、运行 ID 或方法 JSON。

### Decision Studio、节点详情与关系图

这些页面保留现有内容结构和业务逻辑，但统一应用新的颜色、字体、间距、按钮和表单令牌。文化关系图继续作为功能性深色画布例外；其外层导航、工具和详情仍使用 Tonal Focus Review 令牌。

## 6. 数据流与状态

- `workbench-api.ts` 的请求、Bootstrap、保存、运行和轮询契约保持不变。
- 所选节点是画布、Inspector 与上下文抽屉的共同绑定源；只新增或整理客户端布局状态，不复制服务端事实。
- `live`、`cache`、`stale`、`warning`、`error` 和 `blocked` 保持现有诚实语义。状态必须有中文文本或图标，不只显示颜色。
- 加载、空数据、请求失败和不可用操作都提供就地反馈；旧成功状态不得遮盖新失败。
- 任何用户编辑仍按现有保存/运行边界执行，不因视觉重构而自动调用模型或覆盖事实源。

## 7. 响应式规则

- `>= 1280px`：同时显示 60px 命令栏、72px 工具栏、画布、约 210px 上下文抽屉和 330px Inspector。
- `761–1279px`：画布保持主区域；Inspector 与上下文抽屉改为互斥或可收起覆盖层，打开和关闭均可逆，返回焦点到触发按钮。
- `<= 760px`：顶部压缩到约 56px，所有触控目标至少 44px；画布占主要视口，证据/素材/历史与 Inspector 使用全高或近全高抽屉。页面默认可纵向滚动，只有显式进入画布/星图操作模式后才接管单指平移。
- 所有断点禁止页面级横向溢出；中文长标题、状态文本和按钮允许合理换行或省略，但必须能通过详情读取完整内容。

## 8. 可访问性与动效

- 键盘焦点使用 `#345C7D` 与外侧间隔，不能仅靠阴影或颜色差异。
- 主要文字、次级文字和控件状态应满足现有前端质量门的对比度检查；禁用态仍保持可读。
- 弹层、Inspector 和移动抽屉进入后管理焦点，Escape 关闭并恢复触发点。
- 尊重 `prefers-reduced-motion`、`prefers-contrast` 和 Windows forced-colors；减少动效时直接切换绑定内容。
- 节点选择、运行状态和连线关系保留本地化可访问名称与公告。

## 9. 实现策略

首版优先复用现有业务组件和 API 调用，重写设计令牌、工作台壳层、布局样式和必要的结构标记。避免重写已经验证的 React Flow、表单、保存、运行和详情逻辑。其他路由通过共享令牌和基础组件同步视觉，不引入新的依赖或重复状态层。

视觉快照属于有意更新；只有完成桌面与手机人工查看后才更新基线。生成构图仅用于比例、层级和色块参考，不作为像素级实现目标。

## 10. 验证与验收

实现完成前必须实际运行并记录：

- 前端单元测试、TypeScript 类型检查、ESLint 和生产构建。
- Playwright 桌面与手机质量门，覆盖 `/`、Human Decision Studio 和九个节点详情。
- 1440×900 与 390px 视口的工作台、抽屉、Inspector、Decision Studio 和详情页目视检查。
- axe、页面横向溢出、44px 触控目标、键盘焦点、Escape/焦点恢复、画布手势和 reduced-motion/forced-colors 检查。
- API/静态资源请求与浏览器控制台检查，确认没有前端 404、未处理异常或密钥输出。
- 新旧功能核对：工作区 New/Save/Load/Rename、九节点详情、节点运行/保存/导出、证据添加、Human Decision v2、文化关系图和采集状态仍可用。

首版验收标准：网站可本地运行；桌面首屏明显呈现 C2 的五个功能色块；主要工作流与接口不回退；生成构图中的虚构内容没有进入产品；移动端没有横向溢出且关键任务可完成。后续轮次再根据用户现场观感调整色温、比例和密度。
